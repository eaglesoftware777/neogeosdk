# Release Manifests

One source of truth, several views of it. `releases/rom-registry.json` is
written by `tools/rom_registry.py` from the bytes of every file in
`dist/release/` and of every earlier content those files had in git; all the
other files below are generated from the same run.

| File | What it holds | Check with |
|---|---|---|
| `releases/rom-registry.json` | every build of every release file: game, version, semver, `build_id`, target, software list name, database set names, git commit, SDK version, packing time, archive hashes, and size/CRC32/SHA-1/SHA-256 of each file inside | `python3 tools/rom_registry.py --verify` |
| `releases/SHA256SUMS.txt` | SHA-256 of each current file in `dist/release` | `sha256sum -c releases/SHA256SUMS.txt` (from the repository root) |
| `releases/SHA1SUMS.txt` | SHA-1 of the same files | `sha1sum -c releases/SHA1SUMS.txt` |
| `releases/CRC32SUMS.txt` | CRC32 and size of the same files | compare by eye or with a zip tool |
| `releases/ROM_COMPONENTS.tsv` | each ROM and document inside each current package, with size, CRC32, SHA-1 and SHA-256 | spreadsheet or `grep` |
| `releases/external/*.json` | the HBMAME and FinalBurn Neo entries for our sets, and the GitHub release asset list with digests | regenerated by the tool |
| `releases/db-submissions/*.txt` | updated database entries for builds the databases do not describe | see `EXTERNAL_DATABASE_COMPATIBILITY.md` |
| `dist/release/<Prefix>-MANIFEST_<v>.txt` | per-version list written by `make_release.py` (size, CRC32, SHA-256) | section 4 of the integrity report |
| `docs/qa/ROM_INTEGRITY_REPORT.md` | findings: reused names, GitHub asset matches, MAME definition checks, database matches, next versions | read it |

## Registry fields

| Field | Meaning |
|---|---|
| `path`, `file` | where the file lives in the repository |
| `content_no`, `contents_under_this_name` | which of the contents that name has had, oldest first |
| `status` | `current` (the file in `dist/release` now), `replaced` (an older content of a file that still exists), `removed` |
| `prefix`, `game`, `title`, `version`, `semver` | game and version from the file name (`v4` is 4.0.0) |
| `target` | `mame-mvs`, `mame-aes`, `neosd-mvs`, `neosd-aes`, `darksoft-*`, `backbit-*`, `neogeocd`, `document` |
| `build_id` | hash of the ROM parts: the same game bytes give the same id in every package |
| `game_id` | the NGH number in the ROM names (779 for Sky Lance) |
| `git_commit`, `commit_date`, `only_in_pre_rewrite_history`, `pushed`, `tracked` | provenance; `pushed` means the content reached the public repository |
| `sdk_version` | the newest SDK release published on GitHub before the build's commit |
| `build_timestamp` | the newest file time inside the zip, i.e. when it was packed |
| `archive` | size, CRC32, SHA-1, SHA-256 of the file itself |
| `files` | the same four values for each file inside a zip; `part` marks a ROM (`p1` ... `c2`) |
| `mame_definition` | whether the set's own `hash/neogeo.xml` describes the ROMs packed beside it |
| `published` | GitHub release assets with exactly these bytes |
| `external_matches` | database sets that describe this build part for part |

## Reproducibility

`reproducible` is not recorded per build: two clean builds of the same
commit are compared by `docs/qa/BASELINE_AUDIT.md`, and a build is only
called reproducible where those hashes were seen to match.
