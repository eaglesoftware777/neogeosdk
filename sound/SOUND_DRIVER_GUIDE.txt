Neo Geo YM2610 Sound Driver Guide
=================================

Purpose
-------
This file documents the current sound driver in this tree:

- what the driver supports today
- which SDK functions are safe to call from 68k code
- which raw command bytes the Z80 driver understands
- how music, ADPCM-A, ADPCM-B, SSG, and FM are used in practice
- best practices for init, stop, scene transitions, and content layout

This guide is for the current live implementation in:

- `sdk/neogeo.h`
- `sdk/neogeolib.c`
- `sound/driver/driver.asm`
- `sound/tools/mml_compile.py`
- `sound/tools/fm_compile.py`
- `sound/tools/fm_patch_compile.py`
- `sound/tools/ssg_compile.py`
- `sound/tools/ssg_config_compile.py`
- `sound/tools/vrom.py`


1. Sound architecture
---------------------
The Neo Geo sound path here is:

1. The 68000 sends one-byte commands through `REG_SOUND`.
2. The Z80 receives each command by NMI at vector `$0066`.
3. The driver pushes commands into a FIFO in Z80 RAM.
4. The main Z80 loop drains the FIFO and dispatches commands.
5. Timer B IRQ at vector `$0038` advances the music engine.

The YM2610 has four useful sound areas in this driver:

- ADPCM-A:
  Short sound effects, up to 6 hardware channels, one-shot samples.
- ADPCM-B:
  One streamed sample at a time, suited for backing beds, ambience, or long cues.
- SSG:
  Square-wave melody generated by the MML music engine, plus a standalone
  SSG sequencer driven directly by `playSSGTrack(n)` and `soundSetSSGPreset(n)`.
- FM:
  Compiled FM sequencer with a 16-patch table-driven voice bank. `playFMTrack(n)`
  selects from up to 8 compiled FM tracks. `soundSetFMVolume(v)` controls the
  FM output level. Patch definitions live in `sound/fm/patches.fm`.

3. High-level SDK API
---------------------
The public declarations are in `sdk/neogeo.h`.

Use these from game code:

```c
/* Core control */
soundInit();
soundReset();
soundStopAll();
soundStopMusic();
soundCancelFade();
soundSceneReset();

/* Playback */
playMusic(track);
playSFX(sample_a);
playSFXB(sample_b);
playFMDebug();
playFMTrack(fm_track);
soundSetFMVolume(fm_vol);
playSSGTrack(ssg_track);
soundSetSSGPreset(preset);
playInsertCoinSSG();

/* Voice cues */
playVoiceCue(cue_number);
playGetReadyVoice();
playAttackVoice();
playCoinThenReady();

/* Scene helpers */
soundPlayDemoFM(fm_track);
soundPlayTitleMusic(music_track);
soundPlayGameLoop(music_track);

/* Fades */
soundFadeOut();
soundFadeIn();
soundFadeOutSpeed(speed);
soundFadeInSpeed(speed);

/* Volume / tempo */
soundSetTempo(raw_tick_divisor);
soundSetADPCMAVolume(vol_a);
soundSetADPCMBVolume(vol_b);
soundSetSSGVolume(vol_ssg);
```

Behavior:

- `soundInit()`
  Initializes the Z80 driver state, YM2610 timer state, SSG, FM, ADPCM-A, and ADPCM-B.

- `soundReset()`
  Performs a soft reset of driver state. Clears queues, timers, and playback state, and returns to default driver values.

- `soundStopAll()`
  Stops music and all active sound playback immediately without rebuilding full driver state.

- `soundStopMusic()`
  Stops the current music engine and SSG output only. ADPCM playback is left untouched. No arguments.

- `soundCancelFade()`
  Cancels the current fade and restores the stored base volumes for music, ADPCM-A, and ADPCM-B. No arguments.

- `soundSceneReset()`
  Calls `soundStopAll()`, waits 4 ms, then calls `soundReset()`. Use before starting any new scene.

- `playMusic(n)`
  Starts music track `n` from the generated MML table. Valid range: `0..MUSIC_TRACK_COUNT-1`. The track may contain SSG notes plus inline ADPCM-A, ADPCM-B, and FM trigger events.

- `playSFX(n)`
  Triggers ADPCM-A sample `n`. Valid range: `0..ADPCMA_COUNT-1`.

- `playSFXB(n)`
  Triggers ADPCM-B sample `n`. Valid range: `0..ADPCMB_COUNT-1`.

- `playFMDebug()`
  Triggers FM track 0 through the sequencer and auto-stops after a short timer.

- `playFMTrack(n)`
  Starts FM track `n` through the compiled FM sequencer. Valid range: `0..FM_TRACK_COUNT-1` (currently 8 tracks).

- `soundSetFMVolume(v)`
  Sets the FM output level. `v` is `0..15`; written via command $13.

- `playSSGTrack(n)`
  Starts standalone SSG sequencer track `n` from `sound/ssg/`. Valid range: `0..SSG_TRACK_COUNT-1`.

- `soundSetSSGPreset(n)`
  Applies SSG tone preset `n` from the compiled preset table. Valid range: `0..15`.

- `playInsertCoinSSG()`
  Convenience: plays SSG track 2 (insert coin) and applies preset 1. No arguments.

- `playVoiceCue(n)`
  Maps a number 1–9 to an ADPCM-A voice sample:
  1=get ready, 2=oh hey ya, 3=coin, 4=insert coin, 5=start, 6=title, 7=intro, 8=attack, 9=samurai.

- `playGetReadyVoice()`
  Triggers ADPCM-A sample 10 (ready voice cue). No arguments.

- `playAttackVoice()`
  Triggers ADPCM-A sample 11 (attack voice cue). No arguments.

- `playCoinThenReady()`
  Plays the insert-coin SSG sting, waits 250 ms, then triggers the ready voice. No arguments.

- `soundPlayDemoFM(fm_track)`
  Scene reset → set FM volume 0x0C → start FM track `fm_track`.

- `soundPlayTitleMusic(music_track)`
  Scene reset → set ADPCM-A/ADPCM-B mix → play title gong on ADPCM-A →
  start the direct ADPCM-B title theme. The current helper ignores
  `music_track` and always uses `SOUND_BED_TITLE_THEME`.

- `soundPlayGameLoop(music_track)`
  Scene reset → set ADPCM-A/ADPCM-B mix → select a direct ADPCM-B bed from
  `music_track`:
  - `0` = `SOUND_BED_STAGE_ONE`
  - `1` = `SOUND_BED_STAGE_TWO`
  - `2` = `SOUND_BED_ENDING_THEME`

- `soundSetTempo(t)`
  Sets the live driver tempo divisor directly. This is not BPM conversion. `t` is `0..255`; small values are fast and large values are slow.

- `soundSetADPCMAVolume(v)`
  Sets the ADPCM-A master level register value used by the driver. Recommended range: `0..63`.

- `soundSetADPCMBVolume(v)`
  Sets the ADPCM-B playback volume used by the driver. Recommended range: `0..255`.

- `soundSetSSGVolume(v)`
  Sets the SSG music volume used by the music engine. Recommended range: `0..15`.

- `soundFadeOut()`
  Starts a software fade-out using the default speed. No arguments.

- `soundFadeIn()`
  Starts a software fade-in using the default speed. No arguments.

- `soundFadeOutSpeed(speed)`
  Starts a software fade-out. `speed` is `0..255`, where higher means faster.

- `soundFadeInSpeed(speed)`
  Starts a software fade-in. `speed` is `0..255`, where higher means faster.


4. Function argument reference
------------------------------
This section lists every public sound function and the meaning of its arguments.

- `soundInit()`
  No arguments. Call once during startup before any other sound function.

- `soundReset()`
  No arguments. Use when you want a clean driver state for a new scene.

- `soundStopAll()`
  No arguments. Stops music and current effects.

- `soundStopMusic()`
  No arguments. Stops music / SSG only.

- `soundCancelFade()`
  No arguments. Cancels an in-progress fade and restores stored base volumes.

- `soundSceneReset()`
  No arguments. Calls soundStopAll + 4 ms wait + soundReset + 4 ms wait.

- `playMusic(n)`
  `n` selects the generated music track. Valid range: `0..MUSIC_TRACK_COUNT-1`.

- `playSFX(n)`
  `n` selects the ADPCM-A sample. Valid range: `0..11` (12 samples).

- `playSFXB(n)`
  `n` selects the ADPCM-B sample. Valid range: `0..3` (4 samples).

- `playFMDebug()`
  No arguments. Triggers FM track 0.

- `playFMTrack(n)`
  `n` selects the compiled FM track. Valid range: `0..FM_TRACK_COUNT-1` (currently 8).

- `soundSetFMVolume(v)`
  `v` is the FM output level. Valid range: `0..15`.

- `playSSGTrack(n)`
  `n` selects the standalone SSG sequencer track. Valid range: `0..SSG_TRACK_COUNT-1`.

- `soundSetSSGPreset(n)`
  `n` selects an SSG tone preset from the compiled preset table. Valid range: `0..15`.

- `playInsertCoinSSG()`
  No arguments. Plays SSG track 2 with preset 1.

- `playVoiceCue(n)`
  `n` is 1..9. 1=get ready, 2=oh hey ya, 3=coin, 4=insert coin,
  5=start, 6=title, 7=intro, 8=attack, 9=samurai.

- `playGetReadyVoice()`
  No arguments. Plays ADPCM-A sample 10.

- `playAttackVoice()`
  No arguments. Plays ADPCM-A sample 11.

- `playCoinThenReady()`
  No arguments. Plays insert-coin SSG, waits 250 ms, plays ready voice.

- `soundPlayDemoFM(n)`
  `n` selects the FM track. Does scene reset, sets FM volume, starts FM track.

- `soundPlayTitleMusic(n)`
  Current helper ignores `n`. It resets the scene, plays the title gong, then
  starts ADPCM-B bed 0 (`SOUND_BED_TITLE_THEME`).

- `soundPlayGameLoop(n)`
  `n` selects the direct ADPCM-B bed used by the high-level live flow:
  `0` = stage loop 1, `1` = stage loop 2, `2` = ending/results.

- `soundFadeOut()`
  No arguments. Uses the default fade-out speed.

- `soundFadeIn()`
  No arguments. Uses the default fade-in speed.

- `soundFadeOutSpeed(speed)`
  `speed` is `0..255`. Larger values fade faster.

- `soundFadeInSpeed(speed)`
  `speed` is `0..255`. Larger values fade faster.

- `soundSetTempo(t)`
  `t` is `0..255`. Smaller values run the music ticker faster; larger values slow it down.

- `soundSetADPCMAVolume(v)`
  `v` is the ADPCM-A master volume. Recommended range: `0..63`.

- `soundSetADPCMBVolume(v)`
  `v` is the ADPCM-B volume. Recommended range: `0..255`.

- `soundSetSSGVolume(v)`
  `v` is the SSG volume used by the music engine. Recommended range: `0..15`.

- `playSoundtest(index)`
  `index` sends a raw command byte directly to the Z80 driver. Use this only for debug or low-level testing when there is no dedicated wrapper.


5. Best-practice call patterns
------------------------------
Recommended init pattern:

```c
soundInit();
soundSetADPCMAVolume(0x3F);
soundSetADPCMBVolume(0xB8);
soundSetSSGVolume(0x08);
```

Recommended scene reset pattern:

```c
soundSceneReset();   // stopAll + 4ms + reset + 4ms
```

Recommended title music start pattern:

```c
soundPlayTitleMusic(0);   // scene reset + title gong + direct ADPCM-B title theme
```

Recommended game loop start pattern:

```c
soundPlayGameLoop(0);     // scene reset + direct ADPCM-B stage loop 1
```

Recommended FM demo pattern:

```c
soundPlayDemoFM(0);       // scene reset + FM vol + playFMTrack(0)
```

Recommended manual music start (custom volumes):

```c
soundSceneReset();
soundSetSSGVolume(0x08);
soundSetADPCMAVolume(0x38);
soundSetADPCMBVolume(0x45);
soundSetFMVolume(0x0C);
playMusic(0);
```

Recommended one-shot effect pattern:

```c
soundSetADPCMAVolume(0x3F);
playSFX(0);
```

Recommended long ambience/backing pattern:

```c
soundStopAll();
soundSetADPCMBVolume(0xB8);
playSFXB(2);
```

Do not do this:

- Do not spam `soundReset()` every frame.
- Do not start a new ADPCM-B cue every frame; ADPCM-B is a single streamed voice and each new trigger restarts it.
- Do not write directly to `REG_SOUND` from game code unless you also handle the ready handshake correctly.
- Do not assume `soundFadeIn()` and `soundFadeOut()` are magic. They are software fades over the stored base volumes, not hardware envelope commands.


6. Command protocol
-------------------
The 68k and Z80 communicate with one-byte commands.

Safe rule:
Use the SDK functions first. Use raw command bytes only when you need a feature that has no wrapper yet.

Current raw command map in `sound/driver/driver.asm`:

- `$01`
  Driver init.

- `$02`
  BIOS eyecatcher / boot music command.
  The driver maps this to music track 1.

- `$03`
  Driver soft reset.

- `$04`
  Stop all playback.

- `$0A`
  Fade out speed prefix. The next byte is the fade speed.

- `$05`
  Next byte is ADPCM-A volume parameter.

- `$06`
  Next byte is ADPCM-B volume parameter.

- `$07`
  Next byte is SSG music volume parameter.

- `$0C`
  Stop ADPCM-A only.

- `$0D`
  Stop ADPCM-B only.

- `$0E`
  Next byte is raw live tempo divisor.

- `$0F`
  Stop music / SSG output only.

- `$11`
  Cancel fade and restore the stored base volumes.

- `$12`
  Fade in speed prefix. The next byte is the fade speed.

- `$13`
  FM volume prefix. The next byte is the FM level (lower nibble used, 0..15).

- `$14`
  SSG preset prefix. The next byte is the preset index (lower nibble, 0..15).

- `$20` and up
  Music track trigger range (command $20+n starts music track n).

- `$28`
  Direct trigger for ADPCM-B sample 0.

- `$29`
  Direct trigger for ADPCM-B sample 1.

- `$30`
  FM debug tone (starts FM track 0).

- `$31`
  FM track select prefix. The next byte is the FM track index.

- `$32`
  SSG track select prefix. The next byte is the SSG track index.

- `$40` and up
  ADPCM-A trigger range (command $40+n starts ADPCM-A sample n).

- `$80` and up
  ADPCM-B trigger range (command $80+n starts ADPCM-B sample n).

Advanced note:
`sdk/neogeolib.c` contains `playSoundtest(uint16_t index)`, which sends a raw command byte directly. It is useful for debug or for commands that do not yet have public wrappers.

8. MML music engine
-------------------
The MML compiler is `sound/tools/mml_compile.py`.

Supported MML tokens:

- `A B C D E F G`
  Notes

- `+` or `#`
  Sharp

- `-`
  Flat

- `R`
  Rest

- `O`
  Octave

- `<` and `>`
  Octave shift

- `L`
  Default note length

- `T`
  Tempo in MML source

- `V`
  SSG note volume

- `~`
  Loop back to track start

- `@aN`
  Trigger ADPCM-A sample `N` inline in music

- `@bN`
  Trigger ADPCM-B sample `N` inline in music

- `@fN`
  Trigger FM track `N` inline in music

Important:
`@fN` now uses the numeric value. `@f0` starts FM track 0, `@f1` starts FM track 1, and so on through the compiled FM track table.

Important:
`T` inside MML is converted by the compiler into driver timing categories. This is different from `soundSetTempo()` from C, which writes the live driver divisor directly.


9. Tempo behavior
-----------------
This point matters because there are two tempo paths:

1. MML `Tn`
   Compiled tempo. The driver converts MML tempo classes into small frame divisors.

2. `soundSetTempo(t)`
   Runtime override. The value is written directly into `VAR_TEMPO`.

Practical effect:

- Small `soundSetTempo()` values:
  Faster stepping
- Large `soundSetTempo()` values:
  Slower stepping

Recommended runtime values:

- `1` to `5` for direct low-level tempo control

Warning:
Values like `108` or `116` are not BPM in the current runtime API. They are large tick divisors and will slow the music engine heavily.


10. Subsystem guidance
---------------------
ADPCM-A:

- Use for coin, slash, hit, shout, click, short voice, step.
- Best for short one-shot effects.
- The driver rotates across 6 channels automatically.
- The driver uses a software auto-stop table to avoid noisy sample tails.

ADPCM-B:

- Use for ambience, backing loops, drone beds, long spoken phrases, or title background cues.
- Only one ADPCM-B stream should be treated as active at a time.
- Starting a new ADPCM-B cue replaces the previous one.

SSG:

- Use for simple retro melody, arpeggios, menu tones, stings, or insert-coin jingles.
- Two SSG paths exist:
  1. Music engine (playMusic): MML tracks in `sound/mml/` include SSG note events.
  2. Standalone SSG sequencer (playSSGTrack): directly plays a compiled SSG track
     from `sound/ssg/` independently of the music engine.
- `soundSetSSGPreset(n)` applies a tone preset from the compiled SSG config table.
- `playInsertCoinSSG()` is a shortcut for the coin-insert SSG sting.

FM:

- Use as a sequenced FM lead line, melody accent, or atmospheric layer.
- `playFMDebug()` starts FM track 0.
- `playFMTrack(n)` selects any of the 8 compiled FM tracks.
- `soundSetFMVolume(v)` controls FM output level (0..15).
- Music tracks can also trigger FM through the `@f` MML event.
- FM voice parameters are driven by a 16-patch table (`sound/fm/patches.fm`).
  The VAR_FM_PATCH variable selects which patch is active for the current track.


11. Stop and reset rules
------------------------
Use `soundStopAll()` when:

- you want silence immediately
- you are switching title to game
- you are cutting a demo cue before another one begins

Use `soundReset()` when:

- you want a clean driver state for a new scene
- you want to flush pending parameter mode and FIFO state
- you want to restore default tempo and default internal volumes

Use both together when:

- you are entering a major new scene and want predictable sound startup
- call `soundSceneReset()` as a one-liner — it wraps the full stop+reset+wait sequence

Example:

```c
soundSceneReset();
```

Or manually:

```c
soundStopAll();
cyclexms(4);
soundReset();
cyclexms(4);
```


12. Volume notes
----------------
Current driver defaults after init/reset:

- ADPCM-A volume default: `0x3F`
- ADPCM-B volume default: `0xA8`
- SSG music volume default: `0x0F` on init, `0x08` after soft reset
- FM volume default: not set by init; call `soundSetFMVolume(0x0C)` before playing FM
- Fade defaults: fade mode off, stored base volumes match the current defaults

Practical working values used in the current high-level helpers:

- `soundPlayTitleMusic()`:
  - ADPCM-A: `0x34`
  - ADPCM-B: `0xC8`
  - SSG: `0x00`
  - FM: `0x00`

- `soundPlayGameLoop()`:
  - ADPCM-A: `0x30`
  - ADPCM-B: `0xB8`
  - SSG: `0x00`
  - FM: `0x00`

Because the final audible balance depends on source material, ROM encoding, and the YM2610 mixer, treat these as tuning ranges rather than strict rules.


13. Content workflow
--------------------
Music (SSG/MML tracks):

1. Edit or add `.mml` files in `sound/mml/`.
2. Run `make mml` or `make sound`.
3. `sound/driver/music_data.inc` is regenerated.

FM tracks:

1. Edit or add `.mml` files in `sound/fm/`.
2. Run `make fm` or `make sound`.
3. `sound/driver/fm_data.inc` is regenerated.

FM patches:

1. Edit `sound/fm/patches.fm`.
2. Run `make fmpatches` or `make sound`.
3. `sound/driver/fm_patch_table.inc` is regenerated.

SSG standalone tracks:

1. Edit or add `.mml` files in `sound/ssg/`.
2. Run `make ssg` or `make sound`.
3. `sound/driver/ssg_data.inc` is regenerated.

SSG config (tone presets):

1. Edit `sound/ssg/config.ssg`.
2. Run `make ssgconfig` or `make sound`.
3. `sound/driver/ssg_config.inc` is regenerated.

ADPCM samples:

1. Put source WAVs in:
   - `sound/samples/in_wav_a/` for ADPCM-A
   - `sound/samples/in_wav_b/` for ADPCM-B
2. Run `make samples`.
   - The bundled Python WAV converter is used by default.
   - Set `SOX=/path/to/sox` only when you explicitly want SoX.
   - No separate Python `sox` module is required.
3. Run `make vrom` or `make sound`.
4. `sound/driver/sample_table.inc` is regenerated.
5. `out/777-v1.v1` is rebuilt and copied into `roms/neogeosdk/`.

Driver:

1. Edit `sound/driver/driver.asm`.
2. Run `make m1rom` or `make sound`.
   Note: `make m1rom` automatically runs fmpatches, fm, mml, ssgconfig, and ssg first.
3. `out/777-m1.m1` is rebuilt and copied into:
   - `roms/neogeosdk/777-m1.m1`
   - `roms/neogeosdk/sm1.sm1`

Experimental C-driver comparison path:

1. Edit `sound/driver/driver.c`.
2. Run `make m1rom USE_Z80C=1`.
   - This compiles the experimental C path.
   - The final playable M1 still links the authoritative `driver.asm`.
3. Run `make m1rom-c` only when you want the experimental C runtime linked into
   the output M1.
4. Run `make compare-driver` to build both paths and compare the two ROM images.


14. Known limitations
---------------------
Current limitations of this implementation:

- FM sequencer drives one voice on channel 0 (CH2 on port-A). Multi-channel FM
  tracking (up to 6 channels) is not yet implemented.
- FM patch table supports 16 patches; the compiled driver currently exposes 4
  patches at runtime via VAR_FM_PATCH (indices 0–3 active in the inc table).
- The public SDK does not yet expose per-sample stop commands for ADPCM-A or ADPCM-B.
- The public SDK does not yet expose a separate wrapper for BIOS command `$02`
  or the direct ADPCM-B shortcuts `$28` and `$29`.
- Runtime `soundSetTempo()` uses raw driver timing units, not BPM.
- Music, FM, and SSG track numbers depend on alphabetical file order in their
  respective source directories.
- The Win32 sound build uses the same source asset flow as Linux, but shell quoting
  and wildcard expansion differ. Use `make -f MakefileWin32.mak ...` rather than
  trying to run the Linux shell wrappers directly from `cmd.exe`.


15. Recommended design use
--------------------------
For a clean arcade-style project, use the YM2610 like this:

- Boot / eyecatcher:
  short ADPCM-A or BIOS-triggered cue

- Coin / UI:
  ADPCM-A or short SSG stings

- Title opening:
  ADPCM-A gong plus direct ADPCM-B title theme

- In-game loop:
  direct ADPCM-B stage bed by default, with MML/SSG available when you call
  `playMusic()` explicitly

- Long ambience:
  ADPCM-B

- Voice:
  ADPCM-A for short voice, ADPCM-B for long speech if needed

- Scene changes:
  `soundStopAll()` first, then `soundReset()` if the next scene needs a clean state

17. Short checklist
-------------------
Use this checklist when wiring new game code:

- call `soundInit()` during startup
- use `soundSceneReset()` before every major scene transition
- use `soundPlayTitleMusic(n)` for title screen music (handles reset + title bed)
- use `soundPlayGameLoop(n)` for in-game stage or ending beds
- use `soundPlayDemoFM(n)` for FM-only demo scenes
- set FM volume with `soundSetFMVolume(v)` before `playFMTrack(n)` in manual flows
- use `playSFX()` for short effects
- use `playSFXB()` for long backing or ambience
- use `playMusic()` for MML-driven SSG tracks
- use `playFMTrack(n)` for compiled FM tracks (8 tracks available)
- use `playSSGTrack(n)` for standalone SSG sequences (coin, alert, jingle)
- use `playInsertCoinSSG()` for the standard insert-coin sting
- use `playVoiceCue(n)` or `playGetReadyVoice()` / `playAttackVoice()` for voice cues
- use `playCoinThenReady()` for the coin+ready combo sequence
- use `soundFadeOutSpeed()` / `soundFadeInSpeed()` when you need deterministic fade timing
- do not assume track numbers stay fixed if MML file names change
